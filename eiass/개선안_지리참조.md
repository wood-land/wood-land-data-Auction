# eiass 개선안 — 사업지구를 지적도에 정확히 겹치기 (2026-10-31)

기준 사례: DG2026A006 구미 성수지구 (QGIS에서 사람이 지리참조자로 맞춘 것과 자동 추출 노란 폴리곤이 1km 이상 어긋남)

## 1. 왜 틀렸나 (코드·실측으로 확인)
| 원인 | 근거 |
| --- | --- |
| 배경이 지형도(등고선+표고+지번)라 chamfer 정합이 안 됨 | review 사유 `봉우리비 1.01~1.04`(1.15 미만). `extract.line_points` 가 회색·검은 선을 모두 "지적선"으로 쓰는데 이 도면은 대부분 **등고선**이라 연속지적도와 닮지 않음 |
| 3장 중 엉뚱한 도면까지 후보 | 쪽 11 = 평가협의회시, 쪽 12 = **금회(현재) 계획도**, 쪽 13 = 변경내역표. 지금은 점수순 6쪽을 모두 시도하고 구분이 없음 |
| 도면 속 **지번·지목 글자(483-9잡, 산52-26임…)** 는 텍스트가 아니라 이미지 | StreamDocs `texts/11` 이 4개 글자(제목·그림 제목)만 돌려줌 → 좌표가 있는 글자를 공짜로 못 얻음 |
| 계획면적 하나로 축척 고정 | 면적을 잘못 읽거나 도면이 일부만 그려진 경우 축척이 어긋남. 도면에는 **막대 축척(0-20-50-100-200m)과 방위표**가 있어 독립 검증 가능 |
| 검색 중심이 주소 한 점 | `성수리 19번지 일원`만으로 중심을 잡음 |

## 2. 가장 효과적인 방법: "지번 글자 앵커" 정합 (권장 1순위)
지형도·지적도 배경 도면에는 필지 번호가 수십 개 찍혀 있다. 이것을 **제어점(GCP)** 으로 쓴다.
1. 그림 쪽 OCR(한글+숫자, 영역 = 배경 도면부) → `지번+지목` 문자열과 **쪽 px 좌표** 수집 (예: `483-9 잡`, `산52-26 임`)
2. 사업지위치의 **리(里) 이름**으로 법정동 확정 → 브이월드 연속지적도에서 그 리의 필지 중심점·지목을 받음
3. OCR 지번 ↔ 지적 필지를 (법정동+지번+지목) 으로 짝지음 (지목이 붙어 있어 오인식 거름 효과 큼)
4. RANSAC 닮음변환(축척·회전·이동) 으로 짝 맞춤 → 잔차(m)가 곧 정확도. 짝 8개 이상·잔차 3m 이하면 자동 통과
5. 막대 축척 길이/방위표로 축척·회전을 교차 검증
- 장점: 등고선에 영향 없음, 오차를 m 단위로 말할 수 있음, 3~5m 수준 기대
- OCR 도구: 로컬 **EasyOCR/PaddleOCR(한국어)** 이 기본. DeepSeek API는 텍스트 전용이라 **이미지는 못 읽음** → DeepSeek는 OCR 결과를 `지번 형식으로 정리·오인식 보정·리 이름 추출` 하는 텍스트 후처리에만 쓰는 것이 맞음 (이미지 판독이 필요하면 Claude 비전이 가능)

## 3. 선 도면 chamfer 보강 (2순위, 기존 코드 개선)
- 지적선만 남기기: 등고선(갈색·점선·곡선)·글자·건물 면 제거 — 색(HSV)과 선 연속성으로 분리, 글자는 연결요소 크기로 제거
- 지적 래스터에 **도로·하천 면**을 별도 채널로 추가(도면에도 도로가 굵게 있어 구조가 강함)
- 탐색을 2단계로: 넓은 영역을 거칠게(해상도 8m) → 후보 상위 3개를 세밀하게(2m). 봉우리비 기준을 만족하는 후보가 없으면 **포기하지 말고 상위 3개를 후보로 저장**해 사람이 고르게 함
- 중심 위치를 주소 한 점이 아니라 **사업지위치의 지번 일원 → 브이월드 필지 폴리곤 중심**으로

## 4. 도면 쪽 선택 규칙
- 쪽 제목에 `금회` / `변경후` / `최종` 이 있으면 최우선, `평가협의회시`·`변경내역`·`종전` 은 제외 또는 후순위
- 쪽 글자가 4개뿐이라 그림 제목만 믿어야 하므로, 제목 키워드 사전을 늘림

## 5. 개발구역 PNG (이번에 코드에 반영)
`eiass/figures/{사업코드}_p{쪽}.png` — 후보 도면 쪽 전체(긴 변 2400px). 사람이 QGIS 지리참조자에 바로 올릴 수 있다. 공람이 끝나면 원본이 비공개라 **보존 목적**도 있음.
(다음 단계: 경계선 안쪽만 잘라 배경 투명 PNG 로 + 월드파일 `.pgw`/`.points` 자동 생성 → QGIS 에서 열면 곧바로 위치에 놓임)

## 6. 링크 저장 (이번에 코드에 반영)
`projects/*.geojson`, gpkg `사업지구`, `review/*.json` 에 추가:
| 필드 | 값 |
| --- | --- |
| `eiass_url` | `https://www.eiass.go.kr/partcptn/choan/choanEiassView.do?BIZ_CD=…&BIZ_SEQ=…` (GET 으로 열림, 실측 확인) |
| `report_file` / `report_file_seq` | '사업의 개요' 파일명·EIASS 파일번호 |
| `figure_png` | 보존한 도면 PNG 경로 (다음 단계에서 채움) |
※ 평가서 PDF 뷰어 링크는 POST 라 영구 링크가 안 됨 → 상세 링크 + 파일번호로 대신.

## 7. DB에 차곡차곡 쌓는 효율적인 순서
```
[목록] → [상세·링크 저장] → [개요 PDF·도면 쪽 선택(금회)] → [도면 PNG 저장]
   → ① 지번 앵커 정합 (OCR) ──통과(잔차≤3m, 앵커≥8)──┐
   → ② 항공사진 SIFT / 선도면 chamfer(보강판)   ──통과──┤→ [폴리곤 확정 → 지적도 교차(PNU) → gpkg]
   → ③ 둘 다 실패 → 사람 요청(아래)
```
- **신뢰도 등급** 필드 추가: `A`(앵커 정합, ≤3m) / `B`(SIFT·chamfer 통과) / `C`(사람 확정) / `D`(검토후보). QGIS 에서 등급별 색으로 구분
- 정합이 끝나면 **필지 교차 후 폴리곤을 지적 경계에 스냅**(경계선이 필지선과 1~2m 이내면 필지선으로) → 도면 선 두께·벡터화 오차 제거
- 기존 `계획면적 ±6%` 검사는 유지하되, 면적이 맞아도 위치가 틀릴 수 있으므로(이번 사례) **독립 검사 2개 이상**(앵커 잔차, chamfer 일치율, 지목 일치율)을 요구
- 사람이 확정한 결과(`C`)는 이후 자동 개선의 **정답 셋**으로 보관 → 알고리즘 변경 때 회귀 시험(DG2026A006 이 첫 시험 사례)
- 추가는 사업 단위로 파일 하나씩(현재 방식 유지) — 충돌·롤백이 쉬움

## 8. 오차를 줄이는 방법 요약
1. 제어점 다수(지번 앵커) + RANSAC, 잔차를 m 로 기록
2. 축척·방위는 막대 축척·방위표로 교차 검증(계획면적 단독 의존 금지)
3. 지목까지 일치시켜 오인식 제거
4. 최종 폴리곤을 필지 경계에 스냅
5. 같은 사업의 도면이 여러 장이면(금회·종전) 각각 정합해 서로 겹치는지 확인

## 9. 사용자에게 도움을 요청할 때 (규칙)
`review/{사업코드}` 대신 **PNG 를 먼저 보여주고** 요청한다.
> "DG2026A006 구미 성수지구 — 도면 PNG(`figures/DG2026A006_p12.png`)입니다. 지리참조자로 **○○ 교차로, △△ 모서리** 두 점 이상 좌표를 지정해 주세요. 자동 후보(노랑)는 어긋나 있습니다."
- 요청 시 같이 제시: 도면 PNG, 자동 후보가 얹힌 위성 미리보기, 추천 기준점 2~3개(OCR 로 읽은 뚜렷한 지번·교차로)
- 사람이 준 점 2~3개로 닮음변환을 계산해 **자동으로 폴리곤 확정 + PNU 계산** → QGIS 에서 직접 붙이는 일 최소화
